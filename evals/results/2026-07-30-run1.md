## Three harness bugs this run exposed

Every one produced a **wrong number** before it was found. Recorded because the pattern —
a measurement instrument lying in both directions — is the thing to watch for.

1. **Truncated parse → false 50% recall.** A non-greedy regex over nested JSON matched an
   inner object and silently returned 6 of 15 findings. Reported as a fail on a run that had
   actually found the defects.
2. **`correlated_findings` ignored → the important findings invisible.** The report carries
   both `correlated_findings` and `findings`; the parser read only the latter. Rule 7 says a
   correlated finding *replaces* its constituents, so this discarded exactly the highest-value
   catches.
3. **Greedy first-match assignment → false 100% recall.** Defects claimed findings in
   declaration order, so `no-validation-gates` grabbed `CORR-001` (which is actually the
   model-output finding) and `silent-sequence-coercion` grabbed a finding that merely used the
   word "flatten". Replaced with best-first assignment scored across all pairs.

## Two fixture defects this run exposed

1. **Answer key inside the audited directory.** Run 0 scored a perfect 0 false positives on
   `clean-control` while `expected.json` sat in scope — and the auditor said so itself. Keys
   moved to `evals/expected/`; `run_eval.py` now refuses a fixture with an in-scope key.
2. **The seeded defect was unreachable.** `enrichment.json` used a nested `{records: [...]}`
   shape and `segments.parquet` did not exist, so `pd.read_json(...).merge(on="segment_code")`
   raised `KeyError` and the build died before `flatten()` ran. VIGIL found *that* bug
   (`VIGIL-DATA-002`, demonstrated with a repro) — a real defect I had not seeded — but the
   `silent-sequence-coercion` defect could never fire. Fixed: flat enrichment array, real
   parquet with a list column. Verified the defect now manifests, writing `"['EMEA' 'APAC']"`
   into the shipped CSV.

**So the 83% is not a clean read of VIGIL's recall** — one of the six defects was unreachable
in the code it audited. Run 2 measures the corrected fixture.

## Calibration

`self-certifying-manifest`: expected LOW, reported HIGH (inflated 2). Worth review — the
fixture's expectation may be the thing that is wrong. A manifest the recipient is instructed
to verify against, shipped inside the archive it certifies, is arguably more than LOW.
Resolve by argument, not by editing the number to make the run pass.
