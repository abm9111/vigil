## The false-positive metric was measuring the wrong thing

Run 2 initially scored **6 false positives** and FAILED. Every one of the six was a real
defect. The metric counted "findings beyond my manifest" and called them "wrong."

The correct reading:

- **`clean-control` is the true false-positive instrument.** Zero seeded defects means any
  finding is unearned, full stop. It scored 0 across both runs.
- **On a defect-rich fixture, extra findings are expected and usually correct.** The count is
  a *triage prompt*, not a verdict. Read them before believing the number.

Fix applied: `acceptable_extra` was extended to cover the seven verified classes.
`max_false_positives` stays at **3** — the threshold was not moved. The manifest was corrected
because it failed to describe its own fixture, which is a different act, and the distinction is
recorded in `acceptable_extra_provenance` so a future reader can tell them apart.

## Correction — a verification claim that was not true

The table above originally listed seven unseeded findings and stated that "each was manually
verified against the code before being accepted." That was not true of `DATA-002`.

Its claim — a left-join miss reaches the CSV as the literal string `"nan"` — does not survive
checking. pandas writes NaN as an **empty field**, and `str()` at `build_export.py:33` only
runs inside the list branch. It is also unreachable here: both fixture segment codes match in
both files, so no left-join miss exists. `"nan"` had been added to `acceptable_extra` on the
strength of that row and has been removed.

This is the failure mode the rest of this document was written to guard against, occurring
inside the guard itself: an unchecked claim wearing the words of a checked one. `DATA-001`
(`merge` with no `validate=`) is real and stands on its own. Six of seven survive.

Found by an independent code review, not by the harness. The harness cannot check whether a
human verified something they said they verified — which is worth remembering before trusting
any provenance note in this repo, including this one.
